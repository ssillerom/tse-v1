LECCIÓN 0002 · CONTRATOS DE DIMENSIONES

De d_in a d_out

d_in dice cuántos valores recibe cada token; d_out, cuántos valores queremos producir. nn.Linear aprende la transformación entre ambos espacios.

y = x Wᵀ + b

x[B, T, d_in]
W[d_out, d_in]
b[d_out]
y[B, T, d_out]

1. ¿Por qué dos nombres?

Porque una capa reusable no debería asumir que la anchura de entrada coincide con la de salida. Por ejemplo:

projection = nn.Linear(16, 24)
x = torch.randn(2, 8, 16)
y = projection(x)              # [2, 8, 24]

Batch y secuencia no cambian. La capa se aplica independientemente al vector de cada token y solo transforma su última dimensión.

2. Entonces, ¿qué relación tienen con d_model?

d_model es la anchura estable del residual stream del Transformer. En la mayoría de bloques se usa:

d_in = d_out = d_model

Eso hace válida la suma residual x + attention(x). Una referencia que expone d_in y d_out ofrece una interfaz más general; una implementación que solo recibe d_model codifica directamente el caso habitual.

3. ¿Qué hace nn.Linear?

nn.Linear(d_in, d_out) contiene una matriz entrenable W y, por defecto, un vector entrenable b. No mezcla tokens entre sí; mezcla las características dentro de cada token.

En atención se crean tres transformaciones distintas:

Q = W_query(x)  # qué busca el token
K = W_key(x)    # qué ofrece para ser encontrado
V = W_value(x)  # qué información entregará

Aunque las tres reciben el mismo x, tienen pesos diferentes y aprenden tres representaciones diferentes.

4. ¿Qué significa qkv_bias?

Es un interruptor que decide si las tres proyecciones incorporan b:

self.W_query = nn.Linear(d_model, d_model, bias=qkv_bias)
self.W_key   = nn.Linear(d_model, d_model, bias=qkv_bias)
self.W_value = nn.Linear(d_model, d_model, bias=qkv_bias)
FalseQ = xWᵀ
TrueQ = xWᵀ + b

Con d_model=512, activar el bias añade 512 parámetros a cada proyección: 1.536 parámetros QKV en total. Es muy poco frente a las tres matrices, que contienen 3·512² = 786.432 parámetros.

No es una máscara. El bias QKV es un desplazamiento aprendido en el espacio de características. No es el causal mask ni el “attention bias” añadido a los scores.

5. En tu workspace

La implementación actual usa d_model tanto como entrada como salida de Q/K/V. Los tests y scripts todavía intentan construir una clase anterior con d_in/d_out. Son dos interfaces diferentes para la misma idea y ahora mismo están desalineadas.

Además, out_proj = nn.Linear(d_model, d_model) conserva el bias por defecto aunque qkv_bias=False: el flag solo controla Q, K y V.

Comprueba que lo tienes

Si x tiene forma [4, 20, 16] y Linear(16, 24), ¿qué forma sale?

[4, 20, 24].

¿Puede sumarse directamente esa salida con x?

No: 16 y 24 no coinciden. Haría falta otra proyección o usar d_out=16.

¿qkv_bias mezcla información entre tokens?

No. Añade el mismo vector aprendido a cada token de la proyección correspondiente.
